# CreateCMPOR 工作日志

> 记录从分析到附属模组编译、运行验证的全过程。

## 阶段一：分析与文档

1. 解压 `Create-mc1.21.1-dev.zip`、`CompactMachinesPOR-feat-replay-evaluation.zip` 到 `Create-src/`、`CMPOR-src/`。
2. 确认版本环境：两者均为 **MC 1.21.1 / NeoForge 21.1.219**（非 SKILL 默认的 26.1.2）。
3. 深入分析 Create 应力系统、安山传动箱渲染、创造马达，产出 `docs/Create-应力系统技术文档.md`。
4. 深入分析 CMPOR 工厂方块、IO 方块、Core/Machine，产出 `docs/CMPOR-工厂IO技术文档.md`。
5. **关键发现**：CMPOR 是「评估→固化」两阶段系统，工厂固化后完全自包含、无内外实时通道；计划书设想的「内外指向同一内存地址、实时传应力」机制并不存在。已与用户确认，改用「应力作为工厂第四种资源」架构。

## 阶段二：附属模组制作

### 项目搭建
- 在线确认 Create 依赖坐标（`maven.createmod.net`），选定 Create `6.0.10-281` + ponder `1.0.82` + flywheel `1.0.6` + registrate `MC1.21-1.3.0+67`。
- 用 ModDevGradle 2.0.141 搭建 `CreateCMPOR/`，Java 21 toolchain（`C:\Program Files\zulujava\jdk-21`），Gradle 9.2.1。
- CMPOR 0.9.2 jar 作 `localRuntime`，CompactMachines 走 CurseForge maven。

### 编码
- `StressExtensionBlock`（extends `RotatedPillarKineticBlock implements IBE`）+ `StressExtensionBlockEntity`（extends `GeneratingKineticBlockEntity`）：上下轴向接应力，四侧通过 capability 代理转发相邻工厂的物品/流体/能量 handler。
- `StressIOBlock`（extends `DirectionalKineticBlock implements IBE`，含 `POWERED` 激活态）+ `StressIOBlockEntity`：右键激活，按本地应力盈亏作输入/输出，受 `enableStressOutput` 约束。
- 注册：`ModBlocks`/`ModBlockEntities`/`ModItems`/`ModCreativeTabs`，capability 代理，`BlockStressValues.CAPACITIES` 直接注册（避开会抛异常的 `CStress`）。
- 渲染：`ClientSetup` 用 `ShaftRenderer` 绑定两个 BE，复用 `create:` 命名空间模型/纹理。

### 编译
- **构建尝试 #1**：`./gradlew build` → **BUILD SUCCESSFUL**（27s），生成 `createcmpor-0.1.0.jar`。仅 2 个 `EventBusSubscriber.Bus` 过时警告。
- 修复过时 API 后重新编译，无警告。

### runClient 验证
环境为 Windows Server，无 GPU/OpenGL 驱动，runClient 排查过程：
- **尝试 #1**：`GLFW error: WGL: The driver does not appear to support OpenGL` —— 早期窗口创建失败（环境问题，非模组）。
- **尝试 #2**：放 Mesa dll 到 `run/` + 环境变量 —— 无效（DLL 搜索顺序里工作目录不优先）。
- **尝试 #3**：`-Dorg.lwjgl.opengl.libname` 指向 Mesa —— 无效（EARLYDISPLAY 用 GLFW WGL，不走 lwjgl libname）。
- **尝试 #4**：把 Mesa 的 `opengl32.dll`/`libgallium_wgl.dll` 复制到 JDK `bin/`（java.exe 应用目录，DLL 搜索最优先）—— **成功**！`GL info: llvmpipe ... Mesa 26.1.1`，游戏完整启动到主菜单，6 个模组（含 createcmpor）全部加载，无崩溃。仅发现 1 个 blockstate warning：`stress_io.json` 用了 `active`，实际属性名应为 `powered`。
- **尝试 #5**：修复 blockstate 属性名后 —— **成功**，warning 消失，模组加载、配置生成、渲染绑定均正常。

## 备注：Mesa 软件渲染（环境性修改）
为在无 GPU 的 Windows Server 上运行 runClient，将 Mesa3D 26.1.1（llvmpipe）的 `opengl32.dll`、`libgallium_wgl.dll`、`dxil.dll` 复制到了 `C:\Program Files\zulujava\jdk-21\bin\`。这是开发环境的渲染兜底，**与模组本身无关**，正式服务器/有 GPU 的客户端无需此操作。`build.gradle` 的 client run 配置同时设置了 `GALLIUM_DRIVER=llvmpipe`、`LIBGL_ALWAYS_SOFTWARE=1`、`MESA_GL_VERSION_OVERRIDE=4.6` 等环境变量。
