# 49 · 0.5.0 实机验收清单（单一固化工厂 + 互斥模式表）

> **用途**：本轮重构的**实机验收**。所有"能在代码里判定"的项已由独立验证者跑完（50 项脚本 + 对抗性推演，
> 见 §5 引用），本清单只列**必须在游戏里判定**的项。
>
> **判定纪律**：每条写成"可证伪"形式——**出现反例即 FAIL**，不要用"看起来正常"结案。
> 本重构的核心目标是"**堵住 N 倍产能**"，所以第一优先级只有 4 项，先跑它们。

## 1. 第一优先级 —— 先跑这 4 项，它们决定本轮是否成立

### ① A1｜你的原始复现配方：N 种垃圾只应出 **1 个**工厂

**操作**
1. 房间内搭一台**纯输出**产线（复刻你的原场景：内置刷石机 → 铁块），确认不需要任何外部原料即可产出。
2. 放**一个**并行空间输入方块，白名单配 **3 种廉价料**（沙子 / 木棍 / 圆石）。
3. 给每种廉价料接一条"进料 → 销毁装置"的支路（复刻原漏洞的注水路径）。
4. 用启动棒右键评估方块触发评估，等固化完成。

**判定**
- ✅ 固化位置（评估方块原位置）**只有 1 个工厂方块**；其**正上方没有任何新生成的工厂**（**挖开数，别只看视觉**）。
- ✅ 日志出现且**只出现一次** `已在 … 固化 1 个工厂（3 个互斥模式）`。
- ❌ 出现 ≥2 个工厂方块 → **A1 FAIL（漏洞未堵，立即停线）**。

**证据**：固化前后该区域的俯视/侧视截图 + 日志行。

---

### ② A2｜三个模式互斥：同时喂 3 种垃圾，产出**不叠加**

**操作**
1. 承 A1 的那个工厂（内部 3 个模式）。
2. **单模式基准**：只喂"沙子"，输出端接箱子，计满 **120 秒**，记录 `R_base`。
3. 清空箱子，**同时**喂沙子 + 木棍 + 圆石，同样计满 120 秒，记录 `R_all`。

**判定**
- ✅ `R_all ≤ R_base × 1.15`（15% 容差只为吸收计时误差）。
- ❌ `R_all ≥ R_base × 2`（或接近 3 倍）→ **A2 FAIL：互斥不成立，漏洞换皮回归**。

**证据**：两次计量的箱子截图 + 起止时刻（截图带游戏内时间）。

---

### ③ B4-补｜REPLAY 分支不再让整场固化被取消（**本轮新修缺陷的确认**）

> 背景：独立验证者发现「可触发校验只读 `inputRates`，而 **REPLAY 分支的 `inputRates` 恒为空表**」
> ⇒ 只要房间里有并行方块且任一分支判为 **REPLAY**，**整场固化被取消**（0.4.31 没有的新回归）。
> 该缺陷已在本次交付中修复，本项用于**确认修复生效**。

**操作**
1. 搭一条**输出呈周期性/不平稳**的产线（会被判 REPLAY，例如带慢速循环的装置）。
2. 配 1 个并行空间输入方块并白名单 2~3 个物品，启动评估，跑到固化阶段。

**判定**
- ✅ 固化成功，生成 **1 个**工厂（含多个模式），日志 `已在 … 固化 1 个工厂（N 个互斥模式）`。
- ❌ 评估跑完却**什么都没生成**，且收到"存在无法触发的模式"提示 → **B4-补 FAIL（缺陷未修）**。
- 📌 反向确认（防"改过头"）：**故意构造一个真正无法触发的房间**（某个模式的触发物品在房间里根本不被消耗）
  ⇒ 应当**仍被拦下并提示**。若此时也放行，说明修复把校验变成了"永远通过"。

---

### ④ A4｜纯输出 + 零并行方块：**仍能凭空产出**（玩法核心未被误伤）

**操作**：房间内**不放任何**并行方块，搭一台纯输出产线，固化后运行 60 秒。

**判定**
- ✅ 工厂**凭空产出**（不消耗输入），与 0.4.31 相同；护目镜显示输出型应力并向外供能。
- ❌ 工厂不动 / 被闲置 → **A4 FAIL**（把"无并行方块"误判成了"无模式"）。

## 2. 第二优先级（第一优先级全绿后再跑）

| 项 | 一句话操作 | 判定要点 |
|:--|:--|:--|
| **A3** | 每 5 tick 交替喂三种垃圾，计 120 秒 | `R_alt ≤ R_base × 1.15`；>1.5 倍即 FAIL |
| **A5** | 同一台无并行方块的机器，在 0.4.31 与本次构建各固化一次，比速率 | 速率一致（±15%）、tooltip 结构等价 |
| **B1/B2** | 分别只喂模式 1 / 只喂模式 2 / 同时喂两者 | 产物各自正确；同时喂时**只有一种产物增长**（互斥） |
| **B3** | 先喂触发物让其运转，然后全部撤走，观察 60 秒 | 产物不再增长、输入不再被扣、REPLAY 进度不推进 |
| **B4** | RATE 分支 + REPLAY 分支混合固化，分别喂 | 两种模式各自按自己的判定运行 |
| **B5** | REPLAY 跑到半周期 → 切模式 → 再切回 | **从暂停处继续**；不得出现"每秒反复兑现同一高产出秒槽" |
| **B6** | 构造触发集 `{沙}` 与 `{沙, 木棍}` 两个模式 | 同时喂两者时走**更具体**的那个（高特异模式必须可达） |
| **B7** | 构造 `{沙, 木棍}` 但木棍喂不进的模式 | 固化成功即可（该模式不可达属**已知行为**，见 §3） |
| **B8** | 模式 A 需燃料、B 不需；持续投燃料并反复切模式 | 燃料**不丢失**、"以为放得下却实插失败"不得出现 |
| **C1** | 加载 0.4.31 存档的旧单工厂，运行 120 秒 | 行为与存档时一致 |
| **C2** | 加载含旧**工厂组**的世界：通电运行 + 整组还原 | 组内全部可用；整组还原**数量校验通过** |
| **C3** | `/ccmpor factory legacy list` / `revert <room>` / `remove <room>`（OP） | 三条行为正确；**在存档副本上测** |
| **C4** | 同世界内一个旧组 + 一个新单工厂共存运行 | 互不干扰；旧组还原不被新工厂污染 |
| **D1/D2** | 护目镜看待固化工厂 + 挖下看**物品** tooltip | 显示 `模式 i/N：触发「沙」→ 出「铁块」`，**中文名而非注册 ID**；两种 tooltip 一致 |
| **D3** | 故意让某分支评估失败 | 提示形如 `输入为「沙子」的分支评估失败（原因）` |
| **D4** | 打开 Ponder 的并行方块"固化"场景 | 文案不再承诺"N 个工厂堆叠"，改为"互斥模式"（**该场景本轮已重新启用**） |
| **D5** | 对多模式工厂分别用 Create 打包机 / 漏斗 / 溜槽交互 | **模式 2 的触发物品必须能喂进去**（槽位并集的目的）；空槽 `getSlotLimit` 与 0.4.31 一致 |
| **D6** | 输出型多模式工厂上反复切模式，盯护目镜应力读数 | 切换前后**稳定无残留**；空闲时不向外供能 |
| **S4-1** | 把工厂输出端接回输入端成环，不给外部输入，跑 300 秒 | 长期产出 **≤ 单机速率**（不得随时间加速） |
| **S4-2** | 让某模式产物 = 另一模式触发物品；启动后撤走所有外部触发物 | 撤走后**必须停**（产物进的是输出缓存，不构成触发） |
| **S4-3** | 模式 A 产物**故意堆满不取**，然后喂模式 B 的触发物 | 模式 B **照常产出**（不得被 A 的满仓拖停） |
| **S4-4** | 所有触发物撤走，保持 300 秒（若带燃烧需求则先放好燃料） | 不产出、不扣输入、**不烧燃料**、REPLAY 进度不推进 |

关于 B5 的一条说明：设计文档最初写的"切走归零、只会少产"**是错的**（归零 = 反复兑现同一个高产出秒槽，
最高可放大 `patternLength` 倍）。当前实现采用更安全的"**切走保存 / 切回恢复**"，B5 按**该语义**判定。

## 3. 已知"看起来像 bug，其实是设计"——避免误报

| 观察到的现象 | 性质 |
|:--|:--|
| 喂了触发物、但**其它输入不足** ⇒ 工厂卡住不产出，**不会**自动切到别的模式 | **有意为之**（切换必须有显式的触发物增删，避免抖动） |
| 某个模式**实践上不可达**（其触发集里含"喂不进的物品"） | **已知行为**，不是漏洞（互斥仍成立、不超产） |
| 切模式后 tooltip 的"当前模式"最多延迟 **1 秒** | 本轮新增的**限流同步**（1 包/秒/工厂），非卡顿 |
| 旧档工厂组的 tooltip 出现"**（旧版多工厂组）**"字样 | 预期（遗留标识） |
| 旧档工厂组的整组还原要求**所有成员都在场** | 既有设计（0.4.29 起） |
| 工厂被挖下后物品 tooltip 显示"互斥模式：N 个" | 新语义的正常表述 |

## 4. 判定后的处置建议

| 现象 | 建议处置 |
|:--|:--|
| **A1 / A2 / A3 任一 FAIL** | **立即停线**：漏洞未堵，本轮目标未达成 |
| **B4-补 FAIL** | **高危**：合法房间无法固化 |
| A4 / A5 / C1 / C2 FAIL | 回归：旧行为被破坏，必须修 |
